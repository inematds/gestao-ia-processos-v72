Lesson 5 · 20 min

Who does each step

After the redesign, eight steps are left at Horizonte. The question now is not "where do I put the agent?" but: who does each one? A person, a simple rule in the system, an agent, an integration, or someone (or something) operating the screen. Each answer has a different cost, risk, and upkeep. In this lesson you decide step by step, with the reason written down.

Start the lesson

In this lesson you will

  1. 1What stays with people, and why
  2. 2When a simple rule is enough and an agent would be overkill
  3. 3Where an agent is worth what it costs
  4. 4How automation enters a system, in the right order

Objective: decide, step by step, whether it stays with a person, simple automation, an agent, an API integration, or Computer Use, with the reason for each choice.

01 · Five possible executors

Go down the ladder only when the step above does not solve it. Click each step.

The manager decides the executor and the reason. Building the integration is up to IT or the vendor.

Order of choices for getting into a system: service door or connector, flow with a connector, screen automation, Computer Use (Copilot + Agents for Business, INEMA). Each step down is more fragile and more expensive to maintain.

02 · Decide step by step

Four questions, in order. The examples use Horizonte's version 2.0 (fictional study company).

1. Is it judgment?

Apply the test from lesson 3: would two well-trained people, with the same information, always give the same answer? If not, the decision stays with one person, with a name. The system or the agent prepares the information; the person decides.

Requirements stay too: the invoice, the value approval that the policy gives to someone, the registration of a new customer.

At HorizonteDiscount between 5% and 10%: Patrícia decides. New customer: Juliana checks the CNPJ and registers them. Product shortage: Juliana works out with the customer whether to deliver partially or wait.

2. Is it a fixed rule?

If the answer is always the same and the data is already in a system, you don't need an agent. A rule in the system does the same thing every time, costs little, and anyone can check it.

An agent where a rule would do brings a cost per run and a chance of variation where nobody wanted any.

At Horizonte"Discount up to 5% and order up to R$ 5 thousand go through; the rest goes to Patrícia" is a fixed rule in the app. So is the draw of the 10 Monday orders and the picking notice.

3. Does it need to read and converse?

An agent is worth it when the input is free text, each case is a little different, and the work takes several steps to reach the result. It receives the redesigned process and an authority limit, never "do it like the team does."

Microsoft (Work Trend Index 2026, a vendor survey of 20 thousand people in 10 countries, 05/2026) calls the 16% who use agents in multi-step flows and redesign their work Frontier Professionals.

At HorizonteUnderstanding "I want the usual, but with more disinfectant," checking the customer's history, and building the order: that's Hora. Writing out her authority limit action by action is course G3.

4. How does it get into the system?

When data needs to go from one system to another, ask in this order: does the system have a service door (API) or a ready-made connector? If not, is the screen stable enough for screen automation? Computer Use comes last.

You don't build any of this. You ask IT or the vendor the right questions and decide with the answers: cost, who maintains it, what happens if it fails, what record is kept.

At HorizonteTaking the order from the app to the ERP: Rafael asks the GestorPlus vendor whether there is a service door. With no door, screen automation with a record of each entry. Computer Use only if the screen changes, with finance confirming before saving.

Count: agent in 2 steps, simple automation in 4, integration or screen in 1, person deciding or executing in 6. No step is "the agent does everything."

  • Agent on everything. If the count shows an agent on almost every step, check which ones are a fixed rule: a rule in the system is cheaper and more predictable.
  • Computer Use first. Before the screen, ask about the service door. Computer Use is the last step, with confirmation before saving.
  • Step with no owner. Every automatic step has a person who answers for it and notices when it fails.
  • Deciding on an integration without an answer. If the step depends on IT, write the question and the answer date; don't guess.

06 · Summary

Judgment and requirementStay with a person, who receives the information ready.
Fixed ruleSimple automation: cheap, predictable, easy to check.
Free text and several stepsAgent, with a written authority limit and a responsible person.
Getting into the systemService door, connector, screen. Computer Use last, with confirmation.
